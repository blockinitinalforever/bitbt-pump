## 不能照搬为真实功能的内容

以下元素是演示模型或写死数据，不能直接上线：

- `tokenCatalog`、`perpsCatalog`、`candleData()` 中的全部价格、余额、收益、K 线和持仓。
- “12 个永续市场”“3 个对手池”“128 LP”等静态统计。
- Robinhood Chain 永续交易；当前该链尚未部署正式永续合约。
- UI 中“多个独立对手池”的产品表达；当前 v6 合约是每个 market 的共享流动性账本，不是多个独立 Pool ID。
- KOL 等级、邀请返佣、价格提醒、Webhook 密钥等静态结果；必须等对应 API 返回真实状态。
- Split Vault 的示例收款地址和示例收入。

## 不允许回归的现有能力

新 UI 替换期间必须继续保留：

- SIWE 刷新恢复、失焦后 session 校验和 401 统一退出。
- OKX、TokenPocket、Binance Wallet、EIP-6963、WalletConnect 和 Deep Link。
- Logo 本地格式/大小校验、交易成功后上传、失败清理。
- 标准代币与税费代币、买卖税分离、永久税、税收分配、社区收益和自定义曲线。
- DEX 迁移后 Pancake 路由、真实报价绑定、`minOut`、chain/curve/token/quote 校验。
- API 失败时清空原型金额，任何页面都不得展示伪造数据。
- 移动端搜索可见、交易按钮可触达、官方联系方式和 favicon。

## 实施顺序

1. 先将新 UI 作为隔离预览导入，不改变生产入口。
2. 抽离并删除内嵌演示数据，只保留 DOM、CSS、图标和纯 UI 状态切换。
3. 接入市场、实时链上、排行榜、公告、详情和现货交易。
4. 接入钱包与完整发币流程，保持现有高级发行参数。（已完成）
5. 接入 BSC 永续市场、仓位、报价、授权和交易回执；Robinhood 永续保持“未部署”。
6. 接入账户中心、奖励、Vault、开发者工具；无后端能力的入口明确标记“即将开放”。
7. 通过生产门禁后再切换 `/pump`，旧页面在验收完成前保持可回滚。
