# 永续创建杠杆升级计划（2026-09-16）

## 今天的验收范围

- BSC 内测市场继续使用无价值 tBTUSD；不升级 Proxy、不改 Oracle 合约。
- 当前测试 Oracle 的 `maxDeviationPpm=100000`，合约按 `5000 + 2 × 100000 = 205000 ppm` 计算风险保证金，因此最大允许杠杆为 `floor(1000000 / 205000) = 4×`。后端默认创建参数和前端创建页统一显示 4×。
- 用一枚符合现货流动性条件的代币，按“校验 → tBTUSD 授权 → 创建并注入最低 Quote LP → 链上确认”走通；以交易回执成功、真实 marketId、市场已启用和 LP 余额为验收依据。未完成前不宣称交易已可用。
- `standby` 是无请求时 Keeper 按需待命；创建请求需唤醒 Keeper。若链上预检失败，保留明确错误，不用笼统的“服务异常”代替。

## 后续动态参数（独立 PR）

1. 新增只读代币校验接口：输入 token 地址，后端读取其 Oracle 风控参数及现货流动性，返回允许的最大杠杆、结算资产、最低 Quote LP 和不可创建原因；不需要钱包签名，也不收费。
2. 前端仅在地址完整后请求一次校验结果，显示后端返回的上限；创建交易准备接口复用同一计算，并在签名前再次校验。不得把 4×、10× 或协议全局 100× 当成任意代币的实际上限。
3. 分别复审 API、前端的参数一致性和错误提示；通过后逐步部署。

## 将来开放 10× 的条件

现有测试 Oracle 依赖现货池即时报价。不能仅把它声明的最大偏差从 10% 改为更小数值来“解锁”10×，那会掩盖真实风险。应先设计并独立审计可信价格源、偏差控制、流动性门槛、Keeper/清算和偿付能力，再确认链上风险公式允许 10×；完成合约复审、部署与小额闭环验证后，才同步后端和前端上限。正式价值资产上线另走独立审计和风控门禁。
