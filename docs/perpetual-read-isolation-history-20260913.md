# 永续读取隔离与逐笔历史修复

基线：Pump main `23451f5`，API main `e865bfe`。不改 HTML/CSS 设计，不修改合约、不转账、不部署。

## 修复范围

- 仓位、K 线、余额、服务申请、历史、定时配置读取绑定钱包、网络、Provider、Session 版本；市场级请求额外绑定市场，K 线绑定周期。同类请求只有最新返回可以写状态。
- 切链和退出钱包清空个人历史、服务申请、余额及分页状态。旧请求的成功和失败均不能污染新身份。
- 读取失败显示持续可见的 alert，并向调用方抛出错误供现有弹窗处理；不再吞掉失败后显示旧资料或伪装成成功的空 K 线。
- 公开市场的仓位汇总保留独立状态，不再与“我的逐笔记录”混用。
- 我的记录调用 `activity?history=true&wallet_address=...&limit=200`，按区块、日志游标加载更多；开仓、平仓、清算、到期结算按真实事件展示。CSV 仅导出已加载且符合筛选的结果，列明日志索引及入库时间。

## 发布与数据边界

先发布包含 v86 迁移的 API，再发布前端。未升级 API 如果返回旧仓位格式，前端拒绝把它显示成逐笔事件。
历史从新事件索引启用后的后台游标开始积累，不清空游标、不回扫历史、不从仓位汇总编造事件。升级前的完整历史未回补，界面明确提示；空列表不代表钱包从未交易。
API 返回的 `updatedAt` 是入库时间，不是链上时间；CSV 使用 `indexed_at` 列名。
Keeper 余额问题不在本次修改范围，未关闭保护、不为测试唤醒 Keeper 或发送真实交易。

## 验证

新增本地 VM 覆盖钱包/链/市场/Session 切换、同身份乱序返回、服务失败与过时错误、个人历史的钱包绑定/分页/去重/旧格式拒绝。结合既有完整前端测试与 TypeScript、生产构建验证。
本地模拟不是 OKX/TP 实机或生产链上交易验收，不宣称系统不存在其他问题。

实测：`npm test`：105 passed，0 failed，0 skipped；`npx tsc --noEmit`、`npm run build`（含客户端混淆）和 `git diff --check` 均通过。
